1. 目的
本仕様書は、サッシ情報管理アプリにおける内窓系、新築系外窓（一般サッシ）および新築系玄関ドアのRuntime UI実装について、表示項目、表示順、条件表示、Runtime Packageとの責務分離、実装禁止事項、QA条件を標準化するものである。
実装者またはAIは、本仕様書で固定されたUI骨格を独自判断で再設計してはならない。商品ごとの選択肢や成立可否は正式Runtime Packageに従う。
2. 基本原則
UI項目の表示順と基本骨格は本仕様書で固定する。
選択肢、成立条件、Dependency、商品固有の可否は正式Runtime Packageを参照する。
Runtimeに存在しない値をUI側で推測・補完しない。
商品マスター側の不足・矛盾を発見しても、UI実装で商品マスターを変更しない。
明示的な変更指示がない限り、既存項目の削除・統合・名称変更・順序変更を行わない。
条件付き項目は、条件不成立時に非表示または選択不可とするが、実装者判断で項目そのものを廃止しない。
新築系外窓（一般サッシ）は、メーカー → 商品 → 窓種類 → 窓種固有仕様 → 吊元 → サイズ → 色 → 網戸 → ガラス → その他オプションまでを共通UI骨格として扱う。詳細は15章に従う。
全Window Categoryの選択フローは、シリーズ別・メーカー別の独自表示順ではなく、共通のCanonical Semantic SlotとGlobal Window Selection Flow Engineへ正規化する。カテゴリ差は宣言的Extension Slotで表現し、シリーズ専用Selection Flowを新設しない。

4. 内窓系UI 標準仕様
対象例：LIXIL インプラス、YKK AP ウチリモ等。内窓系もGlobal Window Selection Flowに従う。Canonical Semantic Stageは PRODUCT → OPENING → CONFIGURATION → SIZE → FINISH → GLAZING → INSTALLATION / SURVEY → OPTION を維持する。ただし内窓の特注W/H入力は営業操作順を優先し、Category共通のDeclarative Presentation Extension「INNER_WINDOW_FINAL_DIMENSION」により、OPTIONの後の最終営業入力として表示する。これはSemantic Stageを変更したりシリーズ専用Flowを新設したりするものではない。対象シリーズまたは選択状態に存在しない条件項目は非表示としてよい。 クレセント位置を位置指定とした商品では、特注W/Hの後にCategory Presentation Extension「INNER_WINDOW_POST_DIMENSION_CRESCENT_P」として位置寸法Pを条件表示する。

4.1 内窓 サイズ入力・内部派生ルール
現行対象の内窓Runtimeでは、LIXIL インプラス、YKK AP ウチリモともサイズ方式は特注（CUSTOM）のみを有効候補とする。このためsize_modeはユーザー選択項目として表示せず、Runtime / Adapter内部で固定・派生値として保持する。将来、複数のサイズ方式を営業が選択する必要があるシリーズを追加する場合は、本共通仕様をRevisionして扱う。
引違い窓のsize_class（窓 / テラス等）もユーザーには選択させない。W/H、窓種類、建具構成および正式Runtime Ruleから内部評価する。単純なH閾値だけで推測してはならず、複数のRuntime領域が重なる場合は他の成立条件と併せて評価し、それでも一意化が必要かつできない場合はESTIMATE_CONFIRM_REQUIRED / MANUAL_CHECKとして安全に引き渡す。size_classを営業入力に戻して解決してはならない。
特注W/Hは、プルダウン・チェックボックス中心の仕様選択とオプション選択を完了した後、最終営業入力として配置する。W/H入力または変更後は、既に選択済みのガラス・枠・納まり・オプションその他依存項目を正式Runtimeで再評価し、成立しなくなった値をclearまたは再選択要求とする。
内窓 標準Presentation Flowメーカー↓商品↓窓種類↓窓種固有仕様↓本体色↓ガラス仕様↓Low-E性能［該当時］↓ガラス意匠・安全仕様［該当時］↓スペーサー［該当時］↓中空層［該当時］↓枠仕様↓上枠仕様［該当時］↓下枠仕様↓ふかし枠↓ふかし枠詳細［該当時］↓その他納まり / 連窓・段窓［該当時］↓オプション（複数選択可の項目はMULTI_ENUM）↓特注W↓特注H営業判断外：供給形態・最終ガラス構成詳細等は営業Selectorにせず、積算／メーカー確認へHandoffする。
4.2 枠・納まり項目の分離
内窓の「枠仕様 / 納まり」を1つの項目へ集約しない。少なくとも「枠仕様」「上枠仕様」「下枠仕様」「ふかし枠」「ふかし枠詳細 / 補強」は独立Semantic Slotとして扱い、必要なものだけ条件表示する。「その他納まり / 現場条件」も単一値のプルダウンではなく、正式Runtimeが要求する独立field群の表示ブロックとして扱う。
LIXIL インプラスの表示例は下記を標準とする。下記はUI骨格・表示名称の基準であり、各窓種・寸法・ガラス等で実際に選択可能な候補と成立可否は正式Runtime PackageをSource of Truthとする。
LIXIL インプラス｜枠・納まりの分離例枠仕様├─ 標準枠└─ 持ち出し枠   └─ 持ち出し量［Runtimeが要求する場合のみ］上枠仕様［該当時］├─ 標準└─ アジャスト上枠下枠仕様├─ 一般枠（標準下枠）├─ アルミレール└─ 間仕切り下枠ふかし枠├─ なし└─ あり   ├─ 枠構成：3方 / 4方   ├─ 出幅：20 / 40 / 50 / 70 mm   ├─ 補強仕様［該当時］：通常 / 補強一体（50mm 見付大・見付小 / 70mm 等）   ├─ コーナー窓用［該当時］   └─ カーテンレール仕様［該当時］連窓・段窓構成［該当時］├─ 連窓方立├─ 段窓無目└─ コーナー方立
L型引手付障子等、枠・納まりそのものではない仕様は「枠仕様」へ混在させず、窓種固有仕様またはオプションの適切なSlotへ分離する。施工補助部材・アンカー・ねじ等の施工詳細は、通常営業フローへ無条件表示しない。

4.3 YKK AP 中空層Dependency 特則
YKK APの商品では、スペーサーの種類だけを根拠としてガス有無を自動決定してはならない。スペーサーと中空層は別Dependencyとして扱い、正式Runtimeが許容する中空層候補を表示する。
NG: spacer_type -> gas_type をUI側で自動確定OK: spacer_type + その他成立条件 -> Runtimeが許容する中空層候補を表示

4.4 内窓 ガラス選択と営業責務境界
内窓の営業UIでは、メーカー見積・発注上の供給形態、最終ガラス構成ID、板厚組合せ等を、営業が判断する必要のない場合にSelectorとして露出させない。営業が必要とする意味のある選択を「ガラス仕様 → Low-E性能 → ガラス意匠・安全仕様［該当時］ → スペーサー［該当時］ → 中空層［該当時］」へ正規化する。最終構成が営業Scopeで確定しない場合はESTIMATE_CONFIRM_REQUIRED / MANUAL_CHECKとして積算・メーカー見積へ引き渡し、UI側で推測確定しない。
固定値・内部値・メーカー見積側で確定する値を非表示にしても、Runtime内部のDependency・製作範囲評価に必要な情報は保持する。営業UIから非表示にしたことを、メーカー設定が存在しないことと解釈してはならない。
4.5 内窓 オプション複数選択
同時併用可能なオプションを持つfieldはMULTI_ENUMとして扱い、チェックボックス等の加算型UIで複数選択できること。1件選択するたびに既存選択を置換する単一select実装は禁止する。上流条件の変更で一部オプションが不成立になった場合は、不成立値だけをclearし、引き続き成立する選択は保持する。
施工補助材・ねじ・埋木対応等は、通常商品オプションと同一視しない。営業見積依頼に必要な場合はApproved Sales Request / Installation Extensionとして条件表示し、商品コード・数量・正式BOMをUI側で推測せず、積算／メーカー確認へ明示的にHandoffする。
4.6 内窓 特注仕様・ふかし枠付帯仕様
クレセントなし等、メーカーが特注対応可能としているが通常性能・成立性に注意を要する仕様は、通常仕様と同じ自動成立経路へ入れず「特注・要確認」として表示し、ESTIMATE_CONFIRM_REQUIREDで積算／メーカーへ渡す。
ふかし枠にカーテンレール対応仕様が存在する商品では、ふかし枠ありかつ対象出幅・構成が成立する場合のみ「カーテンレール対応」を条件表示する。対象外の出幅・構成へ変更した場合は値をclearする。選択肢・対象出幅は商品ごとの公式Evidence / 正式Runtime / 承認済みExtensionをAuthorityとし、他シリーズから推測転用しない。

5.1 錠仕様の条件分岐
錠仕様は以下の階層で表示する。上位選択に応じて下位項目を条件表示する。

上記名称はUI骨格上の標準表現であり、実際に選択可能な方式・組合せは対象シリーズの正式Runtime Packageに従う。未収録の方式をUI側で追加してはならない。

7. 実装時の禁止事項
本仕様書で固定された項目順を独断で変更する。
見た目を簡潔にする目的だけで項目を統合・削除する。ただし、本仕様書が明示的に内部化を定める内窓のsize_mode / size_class等は、Runtime fieldを保持したままユーザー入力から非表示とするため、この禁止には該当しない。
Runtimeに値が見つからないことを理由にUI項目自体を削除する。
他メーカー・他シリーズの選択肢やDependencyを推測転用する。
UI実装の都合でAuthoring Master、Runtime JSON、runtime_manifest、Registry等を変更する。
スペーサー等の単一項目だけから、Runtime根拠なしに後続項目を自動確定する。
条件不成立となった古い選択値を内部stateに残したまま見積・出力へ渡す。

13.3 ガラスの意味と選択順
ガラス種類→透明・型板等のガラス種→ガラス詳細・Low-E仕様→ガラス追加機能→中空層→スペーサーの相対順を固定する。「ガラス種類」は大分類、「ガラス種」は見え方、「ガラス詳細」はLow-E等の構成・性能詳細、「追加機能」は安全・防災等の付加機能として区別する。
ガラス種はLow-E詳細の選択を待たず選べる。ガラス種は詳細の依存先に含めるが、詳細を「ガラス種選択済みのときだけ表示・必須」とする新しい制約は加えない。ガラス詳細・追加機能の必須性、表示条件、候補数はRuntimeに従う。単一候補の既存自動選択も維持する。
ガラス種が乳白の場合は乳白に対応する追加機能に絞り、乳白以外または未選択の場合は乳白専用機能を除外する。透明から型板等への変更で、成立しているLow-E詳細や追加機能を一律に消さない。
ブリッジ枠等による中空層・スペーサーの固定は、Runtimeにその成立条件がある範囲でのみ適用する。旧13.3の固定値を全仕様へ一律に転用せず、枠・ガラス等の変更時に候補・固定状態を再評価する。
13.4 内はめ仕様と室内外カバー
内はめ仕様はガラスブロックの後、室内側仕上げの前に配置する。ガラスの内押縁等とは別の施工仕様として扱う。内はめ仕様から必要部材を内部判定するが、「内はめ用の必須部材」の確認欄や説明は営業画面に出さない。部材数量・価格の要確認状態は内部で保持する。
室内側のアングルカバー等と室外化粧カバーの大きさ・組合せは、その他オプションに埋め込まず選択フロー上の独立項目とする。本体外観色→室外カバー色、本体内観色→室内カバー色の依存関係をRuntimeで評価し、色を別に任意選択させない。
室内外カバー色の確認欄や連動説明は表示しない。内部の連動値は計算・保存監査に保持する。対応色が未確定の経路は要確認を維持し、近似色や同名色を推測で確定しない。木製ケーシング色など、別部材として独立指定が必要な項目は削除しない。
13.5 最後に表示する採寸寸法と仕上がり寸法
採寸寸法と製品仕上がり寸法の両方を併記する。「採寸入力／仕上がり入力」の入力基準により、選択側を編集可能・必要入力とし、反対側は既存Evidenceに基づく換算結果として読み取り専用で表示する。未入力から寸法を推測せず、入力を消した場合は対応する派生値も消す。
最後に入力した寸法で、前段の障子・網戸・ガラス・製作範囲等も再評価する。マド／テラス区分は仕上がり寸法とマスターの適用範囲から内部判定し、営業へ区分の選択を求めない。未確定・複数成立の場合は要確認とし、独自の境界値を作らない。
居室等の4仕様に対する本項の寸法対と、13.8の参照サッシ・アタッチ枠・汎用カットモールの寸法は混同しない。
13.6 営業画面に表示しない入力
既設上枠見付・既設下枠見付・既設縦枠見付、建物構造、設置場所、使用環境、新設枠の掘出し条件の7入力は削除済みとして扱い、再表示・必須化・既定値の捏造をしない。
室外カバーの候補を、削除した見付入力や保存済みの古い値から絞り込まない。これらを入力しないことは施工適合の自動承認を意味せず、現調・積算・メーカー確認の責務を維持する。
13.7 条件変更時の保持と再評価
上流条件を変更するたびに依存先を再評価する。有効な選択値は保持し、無効な値は解除または再選択要求とする。適用外になった営業入力は非表示にし、営業用の保存・Summary・見積出力から除外する。内部派生値のうち有効なカバー色・必要部材等は計算・監査用として保持する。
変更する条件
再評価と結果
仕様・窓種・枠・障子
下流の候補・表示・必須・固定値を再評価。成立する値を保持し、無効値と適用外入力を除外する。
透明・型板・フロスト等
成立するLow-E詳細と追加機能を保持。ガラス種変更だけで一律Clearしない。
乳白への変更／乳白からの変更
乳白への変更では不適合な追加機能を解除。乳白から離れた場合は乳白専用機能を解除する。

13.8 アタッチ枠と汎用カットモールの分岐
アタッチ枠（TW用／サーモス用）は、新設サッシシリーズ・窓種→参照サッシの共通基本仕様・色・網戸・ガラス→内はめ仕様と連動するアタッチ枠仕様→室内／室外仕上げ→参照サッシのオプションとアタッチ枠のオプション→部材仕様→最後に採寸・既設枠情報・新設サッシ寸法・アタッチ枠仕上がり寸法の順とする。
参照サッシの既存共通フローは維持する。既設枠見込みや下枠立上り等の当該仕様に必要な寸法を、13.6の削除対象7入力と混同しない。サッシ本体寸法とアタッチ枠仕上がり寸法を区別し、アタッチ枠の既存公式換算を保持する。
汎用カットモールは、既設／新設の取付方式・既設窓設備や雨戸等の条件・新旧サイズ関係→新設サッシシリーズ・窓種と参照サッシの共通選択フロー→部材固有の窓枠色→最後に採寸・新設サッシ寸法の順とする。内はめ仕様は対象外とし、アタッチ枠の仕上がり寸法対や換算を新設しない。

19. Global Window Selection Flow 共通仕様
本章は、全Window Seriesの選択フローを1個の共通Selection Flow Contractへ統一するためのUI Authorityである。Generic Rendererの共通化だけではSelection Flow統一済みと判定しない。
19.1 標準Stage
全Window CategoryのCanonical Semantic Stageは、PRODUCT → OPENING → CONFIGURATION → SIZE → FINISH → SCREEN → GLAZING → INSTALLATION / SURVEY → OPTION の順とする。対象シリーズまたは選択中の窓種類に存在しないStage / Slotは非表示としてよい。ただし、カテゴリ共通で明示定義されたApproved Presentation ExtensionはSemantic Stageを保持したまま表示位置だけを変更できる。内窓の特注W/Hは「INNER_WINDOW_FINAL_DIMENSION」としてOPTION後の最終営業入力に表示する。 クレセント位置指定が成立する場合は、INNER_WINDOW_FINAL_DIMENSIONの直後にINNER_WINDOW_POST_DIMENSION_CRESCENT_Pを配置する。 リプラス住宅用の実際の営業表示順と最終寸法入力は13章を参照する。Semantic Stageと表示位置を区別し、既存uiFlowContractの宣言データで扱う。中央カテゴリの正式登録状態は13.9の境界を維持する。
19.2 Canonical Semantic Slot
全ユーザー操作対象Runtime fieldは、Canonical Semantic SlotまたはApproved Category Extension Slotのいずれかへ必ず正規化する。未知fieldを other:* 等へ黙って流してRelease経路へ通してはならない。未Mapping fieldが1件でも存在する場合はUI統合FAILとする。
19.3 Category Extension
新築系外窓、内窓、外窓カバー工法等の差は、別Selection Flow Engineではなく、AFTER_PRODUCT、AFTER_WINDOW_TYPE、PRE_SIZE、POST_SIZE、POST_GLAZING、INNER_WINDOW_FINAL_DIMENSION等の宣言的Extension / Presentation Slotで表現する。シリーズ単位で独自Flowを定義してはならない。
19.4 Single Flow Engine
表示順決定の実行経路は単一のGlobal Window Selection Flow Engineへ集約する。カテゴリ別order関数、シリーズ別display order補正、Adapter独自UI orderは共通EngineのDeclarative Mappingへ移行し、別実行Engineとして残さない。Runtimeのdisplay_orderは、同一Semantic Slot内の補助的relative order以外に使用しない。
19.5 シリーズ固有Flow Logic禁止
共通Renderer / Flow Engineへ if (series === ...)、if (manufacturer === ...)、if (productId === ...) 等のシリーズ固有Flow分岐を書かない。成立可否、Dependency、visibility、required、auto select、derived / fixed値は正式RuntimeまたはSchema AdapterでNormalized Runtime Modelへ渡す。
19.6 Downstream Clear / Transition
manufacturer、product、window_type、configuration、handing、size_mode、size_class、color、screen、glass、installation、dimension、option等の上流値が変更された場合、下流fieldを正式Runtimeで再評価し、不成立となった値をclearまたはrevalidateする。内窓でsize_mode / size_classをユーザー非表示とする場合も内部stateでは評価を継続し、特注W/H入力後は既存選択済みfieldを含めて再評価する。古い値を内部state、Summary、保存データ、見積、出力へ残してはならない。
19.7 Flow Coverage QA
全対象シリーズ × 全対象窓種類 × visibility / required / dependency / size / installation / optionへ影響する全Selector状態からFLOW_SIGNATUREを完全列挙する。FLOW_SIGNATUREは semantic stage sequence + actual presentation slot sequence + visible slot sequence + required set + dependency parent structure とし、UNVERIFIED_FLOW_SIGNATURE_COUNT = 0 を必須とする。
19.8 Browser Flow QA
Desktop 1440×1000、Smartphone 390×844で全Flow Signatureおよび重要Transition Classを確認する。Stage order、Presentation Slot order、field order、label、visibility、required、disabled、auto-selected、derived/read-only、STANDARD、CUSTOM、downstream clear、Summary、save / restore、console error、page error、failed responseを確認する。内窓ではsize_mode / size_classが不要に露出していないこと、特注W/HがOPTION後の最終営業入力に表示されることも確認し、UNVERIFIED_BROWSER_FLOW_CASE_COUNT = 0 を必須とする。
19.9 Future Series Rule
新シリーズ追加時に新しいSelection Flowを作ってはならない。Runtime → Adapter → Canonical Semantic Slot Mapping → Existing Global Window Selection Flow Engineのみを標準経路とする。共通Schemaで表現できない新概念が必要な場合は、シリーズ専用Flowを作らず共通Semantic Slot SchemaをRevisionする。
19.10 Completion Rule
UNMAPPED_USER_FIELD_COUNT = 0、SERIES_SPECIFIC_FLOW_OVERRIDE_COUNT = 0、UNVERIFIED_FLOW_SIGNATURE_COUNT = 0、UNVERIFIED_BROWSER_FLOW_CASE_COUNT = 0、SINGLE_FLOW_ENGINE_GATE = PASS、FLOW_TRANSITION_GATE = PASS、FULL_BROWSER_FLOW_QA_GATE = PASS、FLOW_REGRESSION_GATE = PASS、GLOBAL_WINDOW_SELECTION_FLOW_GATE = PASS の全成立時のみ「窓選択フロー一本化完了」と判定する。

変更内容：LIXIL インプラスのHuman Flow Reviewで確認された商品Fact・UI欠落を反映。ふかし枠40/50/70では「ふかし枠下部補強部材」を「ふかし枠詳細 / 補強」の候補として条件表示する。引違い窓のクレセントは「クレセント有無 → クレセント種類（標準 / キー付き） → クレセント位置（標準位置 / 位置指定）」を分離し、位置指定時は特注W/Hの後に「クレセント位置P」を数値入力として表示し、対象商品の正式P寸法Ruleで再評価する。オプションはメーカー正式名称を優先し、「外窓用 交換用クレセント（汎用クレセント）」「埋め木樹脂材」「真壁取付用ねじ」等を、成立条件に応じて既存のMULTI_ENUMオプション欄へ統合する。抽象的な「和室溝の埋木対応」等へ名称を置換しない。これらの部材・クレセント仕様の適用可否、部材数量・コード・価格は商品Runtime / 積算 / メーカー確認の責務を維持する。
23.1 インプラス追加UI契約
ふかし枠詳細 / 補強：ふかし枠40 / 50 / 70選択時は、正式Evidenceが成立する範囲で「ふかし枠下部補強部材」を候補へ含める。20mmでは表示しない。
クレセント種類：クレセントありの引違い窓で「標準クレセント / キー付きクレセント」を条件表示する。キー付きは有償品として扱い、必要な確認事項を積算 / LIXILへ引き継ぐ。
クレセント位置：標準位置 / 位置指定を分離する。位置指定を選択した場合のみクレセント位置Pを表示する。
クレセント位置P：特注W / 特注Hの直後に配置する。単位mm。0.5mm境界を失わない入力精度とし、正式P寸法Ruleで範囲判定する。範囲内でもメーカー設備等により製作不可となる可能性はESTIMATE_CONFIRM_REQUIREDとして保持する。
オプション表示名：メーカー資料に正式名称がある部材は正式名称を使用する。「埋め木樹脂材」「真壁取付用ねじ」を別概念へ抽象化しない。
交換用クレセント：外窓側の干渉回避用有償品として、オプション欄で「外窓用 交換用クレセント（汎用クレセント）」を扱う。内窓本体のクレセント種類とは別field / 別意味として混同しない。
23.2 v2.1追加QA
ふかし枠40/50/70で下部補強部材が候補に入り、20mmでは入らない。
クレセントありでキー付きクレセントを選択でき、クレセントなしへ変更するとクレセント種類・位置・P寸法がClearされる。
クレセント位置=位置指定のときだけP寸法が表示され、特注W/Hの後に配置される。
P寸法の0.5mm境界を入力でき、正式P寸法Ruleに範囲外なら成立不可/再入力として検出する。
埋め木樹脂材、真壁取付用ねじ、外窓用 交換用クレセントが正式名称でオプションに表示され、MULTI_ENUMとして他オプションと併用選択できる。
24. 2026年10月15日 リプラス表示契約の追記
現行v2.1の13章を、ユーザーが指定したリプラス住宅用の表示順・依存関係へ更新した。商品入口の統合、ガラス種類→ガラス種→Low-E詳細→追加機能、内はめ仕様、室内外カバーの独立配置と非表示の色連動、寸法の最後配置、採寸／仕上がり併記、有効値保持と無効値解除、アタッチ枠・汎用カットモールの分岐を記載した。旧13章のリプラス表示契約は本追記で置換し、14章のv1.2変更点は履歴として保持する。他商品の仕様、商品マスター、Current Registry、中央カテゴリ登録、Formal採用・リリース状態は変更しない。
