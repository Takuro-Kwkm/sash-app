# リプラス住宅用 Global Selection Flow V7 R2

「商品」はリプラス住宅用の1項目。選択後の「リプラスの仕様」で居室・TW・EW・浴室・アタッチ枠2種・汎用カットモールを選ぶ。7構成の既存正式マスターの `01_入力フロー`、各項目表、固定参照先の共通Semantic Contractを根拠に、既存候補UIの表示定義を整理した。Formal採用済みという意味ではなく、レビュー対象の新しい候補である。

## 項目の意味と順序

| 順序 | 表示区分 | 意味・前提 |
|---|---|---|
| 1 | 設置・施工条件 | 建物構造、設置場所、使用環境、施工方法、設置地域、既設窓条件を区別。浴室は改修モード→SB同時交換時の既設開口パターン。 |
| 2 | 窓種・基本仕様 | アタッチ枠等では参照シリーズ→窓種。本体では窓種→枠→建数→マド／テラス→障子・操作仕様。 |
| 3 | 現場採寸・取付条件 | 現場で測るWS/HS、既設枠見込み・下枠立上り。製品寸法と別の項目・区分。現場の取付適否は別途確認。 |
| 4 | 製品寸法 | 寸法指定方法→標準サイズ／製品仕上がりW/H。参照サッシの建数・特注寸法も共通Runtimeの前提順に配置。 |
| 5 | 本体色 | 本体外観色→本体内観色。カバー・部材の色とは区別。 |
| 6 | 網戸 | 窓種、高さ区分等で候補を絞る。 |
| 7 | ガラス | ガラス種類→詳細・Low-E構成→追加機能→ガス→スペーサー。異なる軸を1つの選択欄へ混ぜない。参照先は既存共通Runtimeの独立した軸を保持。 |
| 8 | カバー・部材色 | 本体色と独立した部材の色。内観樹脂カバー等の名称を具体化。 |
| 9 | 新設サッシのオプション | 固定参照先のオプション。リプラス側の追加部材と区別。 |
| 10 | 追加部材・オプション | リプラス側の必要部材・追加機能。 |
| 11 | 選択した部材の仕様 | 木製ケーシングを追加した後に、その色を選ぶ。部材を外すと色もクリア。 |

表示順は現場の前提確認を先に置くPresentation定義であり、共通Semantic Stageの意味を変更していない。既存のGlobal Selection Flow Engineの拡張点だけを使い、商品名分岐や商品専用Form/Resolverは追加していない。現調の数値と製品寸法は別キー・別区分を保持し、原本が要求する現調の別レイヤーと自動製作判定を、この候補の表示だけで代替しない。

## 依存関係の修正

- 窓種→枠・固有仕様。居室の把手障子はテラス、大壁和室用は2枚建。TWの把手障子はテラス、大壁和室用はテラス2枚建。原本04の条件をSelectorへ明記し、前提変更時に無効な障子仕様をクリア。
- EWの障子仕様→複層／トリプル。ガス=アルゴン、スペーサー=樹脂は原本08に従う固定値。TWの専用トリプル・樹脂スペーサーも固定表示。
- 地域→地域限定ガラス。北海道／東北が確認できない間はブロンズを候補へ出さない。TWの資料不一致のグリーン×クリアは非表示を維持。
- 浴室の窓種・枠→ガラス種類→ガス→スペーサー。ブリッジ枠で一般複層や乾燥空気を候補にせず、樹脂スペーサーと整合する条件のみ表示。トリプルは上げ下げ窓FSに限定。
- リプラス部材→木製ケーシング色。新設サッシの参照シリーズ・窓種→固定参照先のフィールド。特注W/Hの分岐も28種の参照Semantic Roleに含める。

各Roleは意味・元表・Source SHA・前提Field・表示区分・Rankを持つ。未定義Role、未宣言Parent、循環／逆順、Source bytesの不一致を拒否し、項目名から施工条件へ推測分類する処理を廃止した。

## 保存済み設定

旧Snapshotは既存のstale表示を保持し、利用者が現在Runtimeで再検証した時だけ新しい分類へ対応付ける。旧ガラス選択の原本値を `configuration_migration.originalSelection` に保持する。共通Editorの既存拡張情報として保存し、TW採用契約でbytes固定されたdomain.mjsは完全に保持する。新しい設定で種類をクリアしても旧版移行は再実行されない。対応できない旧値や条件不足は自動補完せず再確認へ送る。
